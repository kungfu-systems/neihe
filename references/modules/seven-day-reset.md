# 七天生命重塑·微行动

## 何时使用

用户希望制作、修改或理解“7 天生命重塑·微行动打卡”工具时使用。这个模块的重点不是承诺七天改变人生，而是把一个模糊愿望转译成可观察、可保存、可验收的最小行动工具。

## 七天主题

1. 停下来：今天注意到了什么身体或情绪信号？
2. 看见反应：出现了什么自动反应？
3. 理解保护：这个反应可能在帮助自己避免什么？
4. 减少对抗：能否暂时不批评或消灭它？
5. 选择行动：今天最小、最现实的一步是什么？
6. 进入关系：需要表达什么需要或边界？
7. 回顾整合：这七天看见了什么，准备保留什么？

每天至少保留三个输入：

```text
我今天看见了：
它可能在保护我：
我愿意采取的最小行动：
```

## 默认交付

信息足够时，创建一个可以直接在浏览器打开的单文件 `index.html`：

- HTML、CSS 和 JavaScript 写在同一文件中，不依赖外部框架；
- 显示七天主题和三个输入字段；
- 可以标记当天完成，并以温和方式显示“本周留下的观察和行动”；
- 使用 `localStorage` 保存数据，刷新后记录仍然存在；
- 支持手机屏幕；
- 提供带确认的重置操作；
- 明确数据只保存在当前浏览器，不会自动跨设备同步。

如果用户指定了不同交付形式，保留下面的表达和验收边界，不强制生成网页。

## 表达边界

- 不突出连续打卡、断签、清零或击败懒惰。
- 不把漏打卡解释为人格失败。
- 允许从任意一天继续，也允许修改过去的记录。
- 不承诺心理治疗、诊断或七天改变人生。
- 不用羞辱、威胁和纪律惩罚推动行动。

## 验收

生成网页后实际检查：

1. 文件能够打开，控制台没有阻断使用的明显错误；
2. 七个主题和三个输入字段完整；
3. 输入、完成状态和进度刷新后仍然存在；
4. 漏掉某天不会清空后续记录；
5. 手机宽度下主要内容不溢出；
6. 取消重置时数据保持不变；
7. 报告已验证项和仍未验证项，不把“代码已写完”当作验收完成。
