# 项目 Agent 规则

## 何时使用

用户希望为真实项目创建、检查或改进 `AGENTS.md`，让不同 Agent 理解项目结构、常用命令、修改边界和完成标准时使用。

## 工作方法

1. 先检查项目中是否已有 `AGENTS.md`、`CLAUDE.md`、README、贡献指南和测试配置。
2. 从现有文件中识别项目用途、技术栈、目录、命令和安全边界；不要要求用户重复已经能从项目确认的信息。
3. 读取 [基础模板](../../assets/AGENTS.md)，只保留适用于当前项目的部分。
4. 区分已经确认的事实、根据现场做出的合理假设和仍需用户决定的事项。
5. 默认先给出草案；只有用户明确要求写入时才创建或修改文件。
6. 存在同名规则文件时先比较并给出最小合并建议，不整文件覆盖。

## 最小内容

一份有用的项目规则通常需要回答：

- 这个项目解决什么问题，面向谁，当前处于什么阶段；
- Agent 最需要理解哪些目录和文件；
- 安装、运行、测试和构建使用什么真实命令；
- 哪些接口、文件格式、功能和用户数据不能随意改变；
- 哪些操作需要用户确认；
- 什么证据才能说明任务已经完成；
- 哪些检查只能在真实环境或人工界面中完成。

无法从项目确认的命令使用明确占位或列入待确认项，不编造“标准命令”。

## 输出

交付完整草案，并附上：

1. 已从项目确认的信息；
2. 本次采用的假设；
3. 需要用户补充或决定的事项；
4. 写入后应运行的验证命令。
